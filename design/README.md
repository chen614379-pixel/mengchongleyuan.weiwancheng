# 萌宠乱斗 · 前端重构方案 v0.1

> 这一版只交付「框架 + 视觉语言 + 可点原型」，没有改动 `src/`、`assets/`、`js/` 里的任何游戏代码。
> 原型在 `design/prototype/`，用浏览器打开 `index.html` 即可逐屏查看。

## 0. 怎么看

| 入口 | 说明 |
| --- | --- |
| `design/prototype/index.html` | 带工具栏的完整原型，顶部切屏，左右方向键也可切屏 |
| `...?screen=camp&clean=1` | 无外壳、1280×720 原始尺寸，用于截图/比对 |

原型是 DOM + CSS，目的是快速改版；正式实现仍走 Canvas 2D，尺寸与层级以本文件为准。DOM 与 Canvas 的字体渲染会有 1–3px 差异，属于预期。

## 1. 现状诊断：为什么不是「修一修」

以下问题不是审美偏好，是结构性的。证据都在现有截图与源码里。

### 1.1 版式

1. **文字压字、标题重复**。营地同时出现自绘标题和美术底图里烘死的木牌标题（`work/qa/camp-hud-zoom.png`：白字「萌宠乱斗」压在手绘木牌上，「林间营地」又压在下一行）。卡组页标题被页签压住，设置页左栏副标题压住首行（`work/qa/panel-cycle.png`）。
2. **四个面板各自手写绝对坐标**。`src/scene/panel-*.ts` 每页一套常量，没有栅格、没有约束布局。改一句文案或换一个字号就会错位，这是上面那些压字的根因。
3. **没有安全区概念**。`src/platform/screen.ts` 只读 `windowWidth`，等比缩放后还允许横向拉伸到 1.3 倍；刘海、圆角、微信右上角胶囊都没有预留。货币恰好放在右上角，真机上会和胶囊打架。
4. **字号没有下限**。大量 11–13 逻辑像素的说明文字，在 844×390 的手机横屏上只剩 7–9px。

### 1.2 信息结构

5. **两侧各 210px 的名单栏，合计 33% 屏宽，大部分是空槽**（`work/qa/f8-left.png`）。棋盘上每只动物已经有血环，侧栏再把同样的信息列一遍，既重复又浪费。
6. **结算面板盖住整个棋盘**（`work/qa/match-flow.png`）。「伤害构成」大面板从 y=344 铺到 534，正好压在战场中央；三页内容靠左右小箭头翻，没有页签，玩家不知道还有几页。
7. **入口靠画里的木牌**。营地五个入口是美术底图上烘死的招牌，热区必须按像素对齐；玩家看不出哪里能点，也没有主 CTA。
8. **阶段与规则不可见**。回合数、阶段、倒计时、布阵上限（`2 + floor(round/2)`）、利息、克制关系，都没有就地提示，只能靠记忆或试错。
9. **按钮同权重**。结算底部「返回营地 / 再来一局 / 分享战绩」一样大；集市底部「刷新 / 免费礼物 / 收摊」也一样大，主操作不突出。

### 1.3 资产

10. **UI 被烘进底图**。`bg-camp-wide.jpg` 里有招牌、货币、齿轮；`bg-board-wide.jpg` 里有左右空槽、双齿轮、饲养员、底部八个苔藓垫。这导致新版式永远要迁就旧像素，热区也只能跟着烘焙位置走。这是唯一需要美术返工的地方：**出 3–4 张不带 UI 的干净底图**，其余组件全部程序化绘制。

结论：继续在旧版式上挪坐标，只会把压字从左边挪到右边。需要换一套版式系统。

## 2. 从玩法反推界面

核心循环：**布阵 → 观测 → 战斗 → 结算 → 集市**，8 回合；每回合玩家真正要回答的问题只有四个。

| 时刻 | 玩家心里的问题 | 界面必须给出的答案 |
| --- | --- | --- |
| 进入对局 | 我现在该做什么 | 一个主按钮 + 一条阶段带 |
| 布阵 | 我几只、还能放几只、放哪 | 已布阵/上限、半场高亮、双方战力对比 |
| 观测 | 对手是什么阵容 | 迷雾揭开、敌方阵容与关键特技 |
| 战斗 | 谁在赢、为什么掉血 | 血环、伤害飘字、战报 feed、集火目标 |
| 结算 | 我赢在哪、拿到什么 | MVP、伤害构成、奖励、下一局入口 |
| 集市 | 买什么、钱够吗、能不能合成 | 五张货架、阳光/利息/刷新次数、合成标记 |

界面不是把状态全画出来，而是**按阶段只放大当前决策需要的信息**。这是新框架的第一原则。

## 3. 设计概念：森野手账

玩法是「可爱动物在森林草地上自动乱斗 + 集市抽卡 + 克制搭配」。对应的视觉不是科技风，也不是纯扁平 App，而是：

- **环境**：水彩森林、草地、溪流、篝火——保留现有美术语言，但退到背景层。
- **信息**：米色纸面、手绘墨线、细网格——所有文字都必须落在纸上。
- **操作**：木作按钮、黄铜铆钉、厚度阴影——所有可点的东西都像一块真的木牌。

三种材质对应三层信息，玩家不看文字也能判断「这是背景 / 这是信息 / 这是能按的」。

关键词：**绘本、桌游、营地手账、木刻、米纸**。避免：大面积渐变、玻璃拟态、霓虹色、纯白卡片。

### 与旧版的关系

不是把旧界面换皮，而是重排信息层级：

| | 旧版 | 新版 |
| --- | --- | --- |
| 营地 | 全屏插画 + 画里招牌 | 插画舞台 + 底部木作导航 + 明确主 CTA |
| 对局 | 左右 210px 名单 + 中间棋盘 + 底部手牌 | 顶部阶段带 + 中间大棋盘 + 左右 160px 情报栏 + 底部操作坞 |
| 集市 | 挤在牌桌底部的一排小卡 | 独立全屏货架，5 张 224px 大卡 |
| 结算 | 盖住棋盘的三页弹窗 | 一张完整结算纸，复盘按需展开 |
| 面板 | 四套手写坐标 | 一套 PageFrame + 内容槽 |

## 4. 设计原则

1. **舞台优先**：棋盘/场景至少占 70% 画面；HUD 只活在上、下、左、右四条边。
2. **一屏一主动作**：每个阶段只有一个橙色主按钮，固定在右下拇指区；其余动作降为次级纸按钮。
3. **文字不上画**：文字只能出现在纸面或木牌上；插画区只放动物、天气、氛围。
4. **拇指可达**：所有高频操作落在 `y > 480` 或左右边缘；顶部 56px 只放状态，不放需要点的东西。
5. **系统安全**：顶部 56、左右 24、底部 24；右上角固定预留 120×40 给微信胶囊，任何版本都不占用。
6. **数字优先**：战力、血量、阳光用大号等宽数字；比较关系用长度条，而不是再写一句话。

## 5. 设计 token

### 5.1 色板

| Token | 值 | 用途 |
| --- | --- | --- |
| `ink` | `#2B2923` | 主文字、描边 |
| `ink-2` | `#4C473B` | 次级文字 |
| `ink-3` | `#756C58` | 说明文字 |
| `paper` | `#FBF3E0` | 纸面、卡面 |
| `paper-2` | `#F4E6C8` | 纸面暗部、分隔 |
| `paper-3` | `#E9D5B2` | 纸面阴影 |
| `wood` | `#8A5A38` | 按钮、导航、木框 |
| `wood-d` | `#4A2F1D` | 木作暗部、底部操作坞 |
| `moss` | `#5F8B52` | 我方、成功、买入 |
| `moss-d` | `#3F6238` | 我方深色 |
| `ember` | `#E2663A` | 主按钮、当前阶段、危险 |
| `gold` | `#F0BE4E` | 货币、费用、高亮 |
| `dusk` | `#6A5A82` | 敌方 |
| `berry` | `#BF4B3F` | 受击、被克 |
| `sky` | `#79AEB9` | 天气、信息 |

不使用纯黑纯白；所有描边用 `ink` 加透明度，保持手绘感。

### 5.2 字阶

| 级别 | 字号/字重 | 用途 |
| --- | --- | --- |
| Display | 88–96 / 900 | 仅营地标题 |
| H1 | 40–44 / 900 | 页面标题、结算「胜利」 |
| H2 | 30–34 / 800 | 区块标题、集市标题 |
| H3 | 24–26 / 800 | 卡片名、操作坞标题 |
| Body | 18–20 / 600 | 正文、按钮 |
| Caption | 14–16 / 600 | 辅助说明、标签 |
| Micro | 12–13 / 700 | 仅英文副名、角标 |

**下限**：中文正文不小于 18，说明不小于 14；低于 14 只允许英文装饰。原型为了在一屏塞下信息，部分辅助字用了 11–13，正式实现会在 844×390 上逐屏复核，必要时删信息而不是缩字。

字体：`PingFang SC / HarmonyOS Sans SC / Microsoft YaHei`，全部系统字体，不引入字体包。

### 5.3 间距 / 圆角 / 阴影

- 8pt 栅格：4 / 8 / 12 / 16 / 24 / 32 / 48。
- 圆角：纸卡 20、木按钮 18、小标签 10、头像圆。
- 纸面：`2px ink` 外框 + `1px rgba(ink,.18)` 内虚线，偏移 4px 硬阴影。
- 木按钮：底部 6px 实心暗边，按下位移 4px，不缩放。
- 动效：120ms（按压）/ 180ms（切页）/ 240ms（抽屉）；只做位移与透明度，不做弹跳。

## 6. 信息架构

```
营地（唯一入口）
├─ 对战 → 布阵 → 观测 → 战斗 → 结算 → 集市 → 下一回合
├─ 卡组      （PageFrame）
├─ 图鉴      （PageFrame，含段位/商店/设置同一框架）
├─ 段位
├─ 商店
└─ 设置
```

对局不是五个独立页面，而是**同一条阶段带**上的五个状态：顶部阶段带始终可见，当前阶段橙色，倒计时在右侧；玩家永远知道「现在在哪、还有多久、下一步是什么」。

| `Chip` | 高 32 | 货币、费用、状态 |
| `Tag` | 高 24–30 | 克制（绿）、被克（红）、倾向（金）、天气（蓝） |
| `PaperPanel` | 任意 | 2px 墨线 + 1px 虚线内框 + 硬阴影 |
| `Sheet` | 右侧 420 宽 | 复盘、详情，不遮主内容 |
| `Toast` | 底部居中 | 2.1s，单行，不叠多个 |

所有组件以函数形式实现（`drawXxx` / `layoutXxx`），输入是矩形 + 数据，输出是绘制与命中区域；不在组件内部写死坐标。

## 9. 与现有代码的对接

### 9.1 边界

- **不改** `src/core/`（战斗、经济、AI、命令队列）、`src/platform/`（输入、音频、存档）、`assets/`。
- **新增** `src/ui2/`（token、layout、widgets、icons）与 `src/scene2/`（camp、match、panels），旧 `src/scene/` 保留为 fallback，用 `main.ts` 的入口开关切换。
- 复用 `CommandQueue` / `Command`：新界面只改「手势怎么翻译成命令」，不改命令本身。
- 复用现有动物 PNG、卡面 JPG、天气图；短期用程序化面板盖住底图里的烘焙 UI，正式版再出干净底图。

### 9.2 布局

- 用 `layout.stack / row / grid / dock` 计算矩形，替代 `match-layout.ts` 里的绝对常量。
- 关键矩形集中导出：`TOPBAR`、`BOARD`、`SIDE_L`、`SIDE_R`、`DOCK`、`SHELF`、`SHEET`；绘制与命中判定共用同一份，避免「画一套、点一套」。
- 安全区：启动时读 `wx.getMenuButtonBoundingClientRect()` 与 `safeArea`，得到 `insetTop/Right/Bottom/Left`；1280×720 作为设计基准，按 `cover` 等比缩放，不再横向拉伸 1.3。

### 9.3 渲染

- 纸面板、木按钮底、卡片框用离屏 canvas 缓存，按尺寸分桶；文字与数值每帧绘制。
- 目标 60fps；单帧 draw call 控制在 400 以内；不在 `tick` 里创建对象。
- 文本统一走 `drawText`，带最大宽度与省略号，禁止无约束的 `fillText`。

### 9.4 美术依赖

唯一需要新出的资产：**4 张无 UI 底图**（营地、战场、集市、结算），要求不烘任何按钮、文字、空槽、货币。现有底图里的招牌/齿轮/血环槽/苔藓垫全部由程序绘制，这样版式才能自由调整。
